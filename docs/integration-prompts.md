# Prompts para los chats de admin y web

Ejecutar después de revisar el PR de API y completar el despliegue. Reemplazar TU_API por la URL real. Estos prompts no autorizan despliegue ni merge automático.

## Admin

Trabaja en Eddier511/admin-motoapex. Conecta el panel a la API definida en Eddier511/api-motoapex, docs/contract.md, usando VITE_API_BASE_URL=https://TU_API/v1. Lee el contrato actual antes de implementar. Sustituye el login simulado por POST /auth/login, usa Bearer token en memoria, valida /auth/me, revoca con /auth/logout y devuelve al login ante 401. Retira las credenciales predeterminadas. Aplica permisos de interfaz según rol, manteniendo la autorización real en el servidor. Sustituye los mocks de marcas, categorías, motos y leads por lecturas y operaciones API. Usa IDs de servidor; implementa guardado completo con PUT y no muestres éxito hasta recibir confirmación del servidor. Maneja validación, carga, vacío, errores y 429. Persiste moneda, specs, inventario y galerías por color según contrato. No insertes HTML sin sanitización ni guardes secretos de MySQL en Vite. No inventes endpoints: promociones, uploads, usuarios, contenido web e historial no están disponibles; identifica claramente esas funciones pendientes. Conserva el diseño. Verifica compilación y prueba login, CRUD, publicación, precio oculto y leads. Entrega una rama codex/ con PR e instrucciones de configuración; no hagas merge ni despliegue.

## Web

Trabaja en Eddier511/web-motoapex. Conecta el sitio a las rutas /public de Eddier511/api-motoapex leyendo docs/contract.md, usando VITE_API_BASE_URL=https://TU_API/v1. Reemplaza BRANDS, CATEGORIES y MOTORCYCLES mock por datos públicos. Usa IDs de servidor. Adapta los tipos a colorOptions, specs, allowQuote, showPrice y availability reserved/coming-soon/sold-out/available; no conviertas reserved en pre-order. No muestres precios ausentes ni permitas cotización cuando allowQuote=false. Implementa formulario de consulta con POST /public/leads y confirmación solo después del 201, con carga, errores y 429. Mantén el diseño, filtros y galería por color. No expongas tokens de admin ni credenciales DB. No insertes contenido API como HTML crudo. Conserva hero/promociones como contenido estático claramente documentado hasta que existan sus endpoints. Verifica compilación, rutas de marca, catálogo vacío, galerías, precio oculto y formulario. Entrega una rama codex/ con PR e instrucciones; no hagas merge ni despliegue.
